# Control map (planning notes)

**These are planning notes for a future hosted service, which does not exist yet. The open source project makes no compliance claim: nothing here is an audit, an attestation or a certification, and no hosted service is operating.** The map lists which controls the software implements and which are planned. Self-hosted deployments are the operator's responsibility (see the README).

The table shows where each control is implemented, how it is tested and what evidence it produces. It is updated as the software changes. TSC = Trust Services Criteria (CC = Common Criteria/Security, A = Availability, C = Confidentiality). Status "Planned" means not built yet.

**Access-control criteria (CC6.1 to CC6.3).** Roles and permissions, deprovisioning that revokes keys, and the access review give an operator material to use in their own audit: who holds which role, what each role allows, when access was changed (audit log) and when a member's keys were revoked. They support an operator's own access-control evidence. They do not make a deployment compliant, and nothing records that a review was performed.
